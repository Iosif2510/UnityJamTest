# 손님 초상화 구성 시스템 확정 계획

기준일: 2026-11-18. 기준 자료는 업데이트된 **손님 초상화 작업지시서 (MVP).pdf**(9쪽, 작성자 ParkJiu)다. 검토 원본은 `C:/Users/gpota/Downloads/손님 초상화 작업지시서 (MVP).pdf`다. 초상화에 관해 기존 구현·데이터 계획과 충돌하면 이 작업지시서를 우선한다. 이 문서는 그 규칙과 미확정 항목에 대한 MVP 구현 결정을 기록한다. **계획 확정이며 구현 완료를 뜻하지 않는다.**

### GeneratedCustomer와 대사

`GeneratedCustomer`는 인물 ID, 선택 헤어 색 ID(골렘 null), 눈 색 ID를 보관하는 읽기 전용 값이다. 선택 인물의 성별·귀·송곳니와 함께 `CustomerAppearance` 판정 스냅샷을 한 번 만든다. 렌더링과 정답 계산은 같은 선택값을 사용한다. 씬을 왕복해도 재추첨하지 않고 원본 에셋도 변경하지 않는다.

전용 대사 레코드는 `(customerId, diseaseId)`와 대사 후보를 가진다. 증상 구간 구분은 기존 `DialogueSegment`를 유지한다. 같은 키 중복은 오류다. 생성은 정확히 일치하는 전용 후보 → 해당 질병 공통 후보 순서로 선택하고, 둘 다 없으면 시작 오류로 처리한다. 대사 작성·검수는 기획 담당, 참조 연결·검사는 프로그래머 담당이다.

## 4. 주문 생성과 병·잉크 판정

1. 전용 시드 난수로 활성 종족을 동일 확률로 뽑고, 그 종족의 활성 인물을 동일 확률로 뽑는다. 기존 종족 우선 추첨을 유지한다. 인물별·색별 후보는 고정 ID 순서로 정렬한다.
2. 인물에 허용된 헤어·눈 색을 선택한다. 골렘은 헤어 추첨을 건너뛴다.
3. 활성 질병을 독립적으로 선택하고, 둘 이상이면 직전 질병을 피한다. 해당 인물·질병의 대사를 결정한다.
4. 성별·귀·hasFang·헤어 색 ID·눈 색 ID의 판정 스냅샷으로 정답을 계산하고 주문에 고정한다.

병은 남성 네모, 여성 하트, 골렘 동그라미다. 잉크는 현재 `PrescriptionRules.asset`의 아래 순서를 유지한다. 각 행 조건은 AND이며 위에서 처음 맞는 행을 적용한다.

| 우선순위 | 조건 | 예외 | 잉크 |
| --- | --- | --- | --- |
| 1 | 녹색 눈 | 없음 | 1 |
| 2 | 파랑 눈 AND 뾰족한 귀 | 없음 | 2 |
| 3 | 빨강 또는 검정 헤어 | hasFang = true이면 건너뜀 | 3 |
| 4 | hasFang = true | 없음 | 4 |
| 5 | 귀 없음 | 없음 | 5 |
| 6 | 조건 없음 | 없음 | 6 |

골렘의 헤어 없음은 검정 등 다른 색으로 치환하지 않는다. 돌니 골렘은 4번, 나머지는 5번이 된다. 추후 녹색 눈을 넣으면 해당 골렘은 송곳니보다 먼저 1번에 걸린다. 송곳니 여부를 동물종이나 입 그림 이름에서 추론하지 않는다.

## 5. 납품에서 정적 조립까지

납품 경로는 `Portraits/<인물 ID>/POR_<인물 ID>_<레이어>.png`, 프로젝트 수용 경로는 `Assets/Arts/Portraits/<인물 ID>/`로 한다. 원본은 모두 1024×1536 RGBA이며 trim하지 않는다. 같은 중앙 피벗·기준 좌표를 유지하고 인물별 위치 보정은 하지 않는다. 눈 위치 데이터는 레이어 정렬 보정과 구별되는 엔진 생성 홍채 면의 배치값이다.

BASE는 몸·옷·얼굴·귀·입·뜬 눈과 골렘 장식을 포함한다. 홍채 자리만 투명하게 비우고 동공·테두리 음영은 검정 반투명, 하이라이트는 흰색으로 남긴다. 헤어 아래 이마·머리 윤곽도 복원한다. EYE_CLOSED는 홍채 구멍을 포함한 뜬 눈 전체를 인물 피부색으로 덮고 감은 눈을 그린다. 별도 IRIS·MOUTH 원본은 필요 없다.

헤어는 명도 70~100%의 밝은 회색조, 눈썹은 BASE의 짙은 중간색, 골렘 장식은 BASE의 최종 색을 사용한다. 긴 머리는 4장, 짧은 머리는 3장, 골렘은 2장이다. 긴 머리 인원 L에 대해 인물 PNG 수는 `62 + L`, 공통 슬라임 포함 `63 + L`이다.

`PortraitView`의 논리적 표시 순서는 아래부터 다음과 같다.

```text
PortraitView (원본 기준 1024×1536, 표시 시 2:3 유지)
├─ HairBack       선택, 헤어 색 곱하기
├─ IrisColor      엔진 생성 단색 사각형 1~2개, 눈 색
├─ Base           필수
├─ EyeClosed      필수, 평소 숨김
└─ HairFront      골렘 외 필수, 헤어 색 곱하기
```

PNG 레이어는 같은 RectTransform 크기·앵커·피벗을 사용한다. 홍채 면은 지정 눈 영역만 덮고, 투명한 인물 외곽·입·귀의 빈틈에서는 보이면 안 된다. 크게 만든 전면 단색 판은 사용하지 않는다. 모든 초상화 Graphic의 Raycast Target은 끈다.

정적 임포트 기준은 Sprite (2D and UI), Single, 중앙 피벗, 원본 크기 유지, 알파 보존, Bilinear, mipmap 없음, 최초 검수 시 무압축이다. 리깅 단계에서는 원본 캔버스 좌표를 유지하며 본·웨이트용 메시를 만든다. 임포트·리깅·프리팹과 `.meta`는 프로그래머가 관리한다.

Sprite Atlas는 정렬을 자동으로 해결하거나 인물별 로드를 보장하는 기능으로 취급하지 않는다. 초기 MVP는 원본 Sprite 직접 참조로 통합하고, 실제 메모리와 패킹을 확인한 뒤 별도 최적화한다. 향후 Atlas를 적용하면 회전 패킹을 끄고 원본 rect/pivot·UV·본 변형 호환성을 검수한다. 현재 방식은 카탈로그의 직접 참조 때문에 텍스처 전체가 로드될 수 있다. 인물 단위 실제 지연 로드가 필요하면 별도 에셋 로드 경계를 도입하며, 손님이 한 명이라는 이유만으로 메모리가 한 명 분량이라고 주장하지 않는다.

## 6. 움직임과 uGUI 연결

깜빡임 간격은 3~5초, 닫힌 눈 표시는 0.1초를 초기값으로 둔다. `RoundTuning`에 간격 최소·최대, 닫힘 시간, 호흡·고개·헤어 세기를 둔다. 깜빡임 난수는 주문 생성 난수와 분리한다. 접객과 처방에서 같은 손님을 복원하고, 숨김·교체 시 깜빡임 상태와 타이머를 정리한다.

본 움직임은 작업지시서대로 **Unity 2D Animation**을 사용한다. 공통 리그는 Root → Body → Head와 HairFront/HairBack 분기를 갖고 인물별 위치·웨이트를 저작한다. BASE는 호흡·고개 기울임, 헤어는 고개 추종과 약한 추가 흔들림을 가진다. 홍채 면은 Head 본에 귀속하고 EYE_CLOSED는 BASE 눈 주변과 동일한 변형을 따라야 한다. 움직이는 동안 눈과 귀를 가리거나 홍채 색이 새지 않아야 한다.

**기술 연결 방식:** `SpriteSkin`은 일반 uGUI `Image`를 자동으로 변형하지 않는다. 현재 프로젝트에는 `com.unity.2d.animation` 직접 의존성도 없다. 따라서 본 구현 단계에서 패키지와 버전을 확인하고, 2D Animation 변형 메시를 uGUI에 전달하는 `PortraitSkinnedImage : Image` 어댑터를 만든다. 이 어댑터는 변형 위치·UV와 Image의 색을 UI 메시로 전달하고, 색 처리에는 기본 UI 렌더링과 `Image.color`를 유지한다. Atlas UV, 마스킹, 갱신 시점도 어댑터의 확인 범위다. 특정 패키지 API의 존재나 호환성은 아직 검증하지 않았다.

정적 Image 조립을 먼저 완료한 뒤 샘플 한 명으로 BASE·감은 눈·홍채·헤어의 본 추종을 확인하는 것을 본 제작의 선행 조건으로 둔다. 어댑터가 성립하지 않으면 해당 기술 실패를 보고하고 렌더링 경계를 재결정한다. 전체 이미지를 단순 흔들기만 한 상태를 Unity 2D Animation 본 작업 완료로 처리하지 않는다. 이 위험 때문에 22명 리깅을 먼저 진행하지 않는다.

## 7. 카운터 수명과 엔딩

`OrderSceneView`가 공유 `PortraitView`에 주문의 GeneratedCustomer를 전달한다. Consult와 Prescribe에서 같은 외형을 표시하며 창고 왕복 시 인물·색은 유지한다. RoundDirector는 주문 값만 보관하고 Image·본·씬 오브젝트를 보관하지 않는다.

몸 색 변화는 각 레이어의 평상시 색에 같은 엔딩 틴트를 곱한다. 헤어·눈 색과 전체 틴트를 별도 상태로 저장하고 매번 원본에서 다시 계산해 누적 착색을 막는다. 감은 눈과 홍채 면도 빠뜨리지 않는다. 슬라임 반응은 일반 레이어와 본·깜빡임을 멈추고 `POR_SLIME_BASE.png` 한 장으로 교체한다. 새 주문은 엔딩 색·슬라임·이전 리그를 정리한다. 반응 선택과 점수는 기존 RoundJudge 결과를 공통으로 사용하며, 이번 초상화 계획에서 채점 우선순위를 바꾸지 않는다.

## 8. 제작·승인 흐름과 구현 순서

아트 적용 도구는 [아티스트 에셋 적용·플레이 테스트 계획](ARTIST_WORKFLOW_PLAN.md)을 따른다. Customers·색 SO의 Inspector에서 Sprite·색 참조·눈 영역을 직접 연결·저장한다. **초상화에 한해 `Assets/Scenes/Tests/PortraitTest.unity`를 구성**해 실제 PortraitView와 합성·색·홍채·깜빡임·본·엔딩 모듈을 개별 연결하고 Play로 확인한다. 전용 씬은 전체 주문·질병 데이터 없이도 선택 인물의 모듈을 확인하며, SO 입력만으로 재현한 뒤 실제 카운터에서 인물·색 고정 통합 플레이를 수행한다. 씬 로컬 덮어쓰기는 원본에 자동 저장하지 않는다. 모듈별 입력·조작·검수 경계는 아티스트 계획의 전용 씬 항목을 따른다. 전용 프리뷰 창은 필수가 아니다. 눈 영역은 프로그래머가 초기 설정하고 아티스트가 Inspector에서 조정할 수 있게 한다. 본 제작·판정 속성 관리 책임은 유지한다.

`인물 초안 → PNG 분리·보정 → 파일 검사 → 인물/색/눈 위치 연결 → 엔진 샘플 승인 → 나머지 제작 → 본 리깅·전체 검수 → Active → 빌드·종이 자료 리비전 확정`

아티스트 A는 생성·보정·PNG와 합성 미리보기를 담당한다. 기획은 인물 고정 속성·직업 대사·색 이름의 의미를 확인한다. 프로그래머는 임포트·눈 위치·리깅·판정·엔진 검수를 담당한다. 파일 교체 때 인물 ID와 수정 내역을 기록하며, 의도적으로 없는 HAIR_BACK과 골렘 헤어를 납품 목록에 명시해 누락과 구분한다.

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 후속 인물 스키마, 색 테이블, ID 이행, 속성 기반 잉크 판정 | 임시 3인으로 시드 주문과 병·잉크를 재현하고 인물·질병·색 누락은 오류로 확인한다. |
| 2 | 정적 PortraitView와 눈 사각형 편집 | HUM_M1, ELF_F2, GOL_G3를 PDF 순서대로 선행 통합한다. 허용 색 전부와 깜빡임을 확인한다. |
| 3 | 2D Animation 패키지·리그·uGUI 어댑터 | 샘플 한 명의 본 변형에서 BASE·감은 눈·홍채가 어긋나지 않고 색 곱하기가 유지된다. |
| 4 | 수인·송곳니와 나머지 인물 제작·연결 | 추가로 BST_M1을 확인한 뒤 나머지를 확장한다. 22명 속성과 눈 영역, 선택 레이어를 검사한다. |

데이터 검사에는 인물 호출코드 중복·형식, race/variation/gender/earType 일치, 필수 Sprite, 색 ID와 종족별 허용값, 골렘 헤어 없음, 눈 영역 범위, 전용 대사의 인물·질병 참조, 깜빡임 수치, 슬라임 참조를 추가한다. 제작 중에는 Draft를 허용하며 최종 시연 승인에서는 활성 22명과 전체 색 조합을 확인한다.

잉크 검사·미리보기·사용처 조회는 기존 파츠 조합 대신 인물 × 허용 색 조합을 순회한다. 프리뷰는 호출코드·선택 색·고정 성별/귀/송곳니·병·잉크·적용 규칙·선택 대사를 표시한다. 데이터 리비전·시드·직전 질병이 같으면 동일 주문을 재현한다.

시각 검수는 실제 카운터 배경·대사창 위에서 1920×1080 기준 높이 648px(60%)로 한다. 색 이름, 귀, 송곳니, 눈높이, 밝은 헤어, 움직일 때의 틈·색 누출과 감은 눈의 완전한 덮임을 확인한다. 데이터 검사 통과만으로 화면 검수를 대신하지 않는다.

## 9. 기존 코드 이행 범위와 이번 작업의 경계

후속 구현에서 변경할 대상은 CustomerCatalog/CustomerProfile/PortraitPart, CatalogLoader의 인물 ID 검사·조회, OrderGenerator/GeneratedOrder, PrescriptionRules 조건 접근, CatalogValidationMenu의 조합 순회, OrderSceneView와 초상화 뷰, RoundTuning, PotionCatalog 색 참조, Customers 및 신규 색 에셋이다. 대사 override는 DiseaseRecipeCatalog에 추가한다. 기존 테스트용 인물 ID를 새 호출코드로 바꾸는 명시적 대응표를 만들고 참조·프리뷰 입력을 함께 갱신한다. 이름만 바꿔 기존 직렬화 파츠를 새 스키마로 읽었다고 간주하지 않는다.

이 계획 작성에서는 문서만 변경한다. 런타임 코드·씬·에셋·패키지 설치·Play Mode·빌드 검증은 수행하지 않았다. 후속 구현 시 기존 Editor 사용에 관한 AGENTS.md와 프로젝트 검증 범위를 따른다.
