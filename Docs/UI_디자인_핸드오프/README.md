# 시끄러운 포션공방 — 인터페이스 디자인 핸드오프

2D 디자이너에게 넘기는 작업 안내서다. 2026-11-23 기준.

## 1. 맡길 일

온라인 협동 모드에서 새로 생긴 화면들의 인터페이스 그림이다. 지금은 코드로 급히 만든 임시 화면이라 기존 화면과 어울리지 않는다.

| 순위 | 화면 | 지금 상태 | 참고 파일 |
| --- | --- | --- | --- |
| 1 | 위층 공방 (해설자 화면) | 임시 3단 배치 | `참고_현재화면/102_loft_grid.png`, `103_loft_result.png` |
| 2 | 역할 고르기 (표지 + 위층/아래층 버튼) | 임시 | `참고_현재화면/50_briefing.png` |
| 3 | 이동 중 화면 ("아래층 카운터로 가는 중…") | 임시 | `참고_현재화면/51_travel.png` |
| 4 | 방 만들기·들어가기 창 | 임시 | `참고_현재화면/20_online_panel.png` |

접객, 창고, 포장, 결과 화면은 이미 완성돼 있고 이번 범위가 아니다. 새 화면의 그림체를 기존과 다르게 잡는 경우에만 함께 손본다(5장 참고).

## 2. 게임을 한 문단으로

두 사람이 하는 협동 게임이다. 아래층 플레이어는 손님을 보고 증상을 말로 전하고, 창고에서 재료를 집어 약을 만든다. 위층 플레이어(해설자)는 손님을 보지 못하고, 스승이 남긴 손글씨 메모 8장만 가지고 있다. 둘은 음성으로만 정보를 주고받는다. 한 손님당 제한 시간은 3분이다.

## 3. 위층 공방: 확정된 흐름

기획자와 합의한 해설자의 행동 순서다. 화면은 이 순서를 따라가야 한다.

1. 왼쪽 탭(안내서 / 질병과 재료 / 포장) 중 하나를 누르면 그 탭의 종이들이 탁자에 깔린다. 종이는 왼쪽에서 오른쪽으로 날아와 놓인다.
2. 탁자의 종이 한 장을 누르면 그 종이가 크게 펼쳐진다. 스크롤 없이 한 장이 다 보여야 한다.
3. 펼친 상태에서 읽고, 아니면 옆 장으로 넘긴다. 탁자로 돌아가지 않고 바로 넘긴다.
4. 맞는 장을 찾으면 "찾았어!"를 누른다. 아래층에 "창고로 내려가라"는 신호가 간다.
5. 종이는 펼쳐진 채로 남고, 해설자는 그대로 재료 생김새를 읽어 준다.

화면 상태는 두 가지다.

| 상태 | 보여야 하는 것 |
| --- | --- |
| 탁자 | 탭 3개, 탁자 위 종이들, 남은 시간, 아래층이 지금 무엇을 하는지 |
| 펼침 | 펼친 종이 1장, 앞뒤 넘기기, 몇 번째 장인지(예: 3 / 6), "찾았어!", 탁자로 돌아가기, 탭 3개, 남은 시간, 아래층 상태 |

지켜야 할 조건:

- 남은 시간과 아래층 상태는 종이를 펼친 동안에도 가려지지 않는다.
- 탭 세 개는 쓰임이 다르다. "질병과 재료"는 손님마다 길게, "포장"은 손님마다 짧게, "안내서"는 처음 한 번 본다. 크기를 다르게 해도 된다.
- "포장" 탭은 종이가 한 장뿐이라 누르면 바로 펼쳐진다.
- "찾았어!"는 펼친 상태에만 있다.
- 입력은 마우스뿐이다. 누를 것은 적고 커야 한다.
- 병명은 화면 어디에도 쓰지 않는다. 메모에는 약 이름만 나온다. 오른쪽에 병명 목록을 두는 안은 뺐다.

결과는 손님이 나간 뒤 화면 가운데에 카드로 뜬다. 기존 결과 화면의 양피지 카드와 도장을 그대로 쓴다.

## 4. 만들 부품

기획자가 원하는 것은 늘어나고 줄어들 수 있는 조립식 부품이다. 배경 한 장에 칸을 파 넣는 방식은 쓰지 않는다. 칸 수가 바뀌어도 같은 부품을 더 쌓으면 되어야 한다.

| 부품 | 상태 | 비고 |
| --- | --- | --- |
| 탁자 바닥 (펠트) | 1 | 가로세로로 늘어남. 모서리와 변을 나눠 그린다 |
| 탭 버튼 | 기본, 선택, 마우스 올림, 깜빡임(안내) | 3개가 같은 부품. 글자는 코드로 얹는다 |
| 탭이 놓이는 띠 | 1 | 위아래 마감 + 늘어나는 가운데 |
| 큰 버튼 "찾았어!" | 기본, 마우스 올림, 눌림, 비활성 | 글자는 코드로 얹는다 |
| 작은 버튼 (탁자로, 넘기기 화살표, 닫기) | 기본, 마우스 올림, 눌림 | |
| 쪽 표시 점 | 안 본 장, 본 장, 지금 장 | |
| 시간 막대 | 틀, 채움, 모래시계 | 창고 화면 것(`Timer_Frame`, `Timer_Fill`, `Timer_Hourglass`)을 써도 되고 새로 그려도 된다 |
| 아래층 상태 표시 | 접객 중, 창고, 포장, 결과 | 글자는 코드로 얹는다 |
| 화면 이름표 "위층 공방" | 1 | 기존 붉은 이름표를 써도 된다 |
| 창 틀 (방 만들기, 역할 고르기용) | 1 | 가로세로로 늘어남 |
| 입력 칸 (방 코드) | 기본, 선택 | |
| 배경 | 위층 공방 1장, 이동 중 1장 | 1920×1080 |

늘어나는 부품은 9분할(모서리 4, 변 4, 가운데 1)로 쓸 수 있게 그린다. 모서리 장식은 변으로 넘어가지 않게 하고, 변과 가운데는 늘려도 티가 나지 않는 무늬여야 한다.

메모 종이 8장은 이미 있다(`메모_8장/`). 지금은 세로(1440×2032)인데, 펼쳤을 때 스크롤 없이 보려면 가로 16:9가 유리해서 가로로 다시 뽑을 계획이다. 종이가 놓일 자리는 가로 16:9 비율로 잡는다.

## 5. 그림체

아직 정해지지 않았다. 디자이너가 제안해 주기를 바란다.

- 지금 그림체: 각진 면이 보이는 로우폴리 느낌의 채색. `기존_UI_자산/`과 `참고_현재화면/`에 있다.
- 기획자가 원하는 방향: 선 없이 면으로만 그리고, 채색 밀도가 높은 그림. 가장 밝은 부분에 형광 느낌이 없어야 한다. 참고 그림은 `참고_시안/ref_a.webp`, `ref_b.webp`이다(색감과 덩어리감 참고용이고, 그 안의 캐릭터나 로고를 따라 그리는 것은 아니다).
- 구조의 영감: 카드 게임의 덱 편집 화면처럼, 왼쪽과 오른쪽 부품이 개수에 따라 자연스럽게 늘고 주는 구성. 다른 게임의 그림을 그대로 가져오지 않는다.
- 기획자는 기존 화면의 그림체를 전면 수정하는 것도 열어 두고 있다. 새 그림체가 기존 화면과 어긋나면 기존 UI(양피지, 이름표, 버튼, 시간 막대)까지 다시 그리는 범위로 넓어진다. 범위는 시안을 본 뒤 정한다.

`참고_시안/`의 그림은 방향을 찾으려고 이미지 생성으로 뽑아 본 것이다. 기획자가 마음에 들어 한 안은 없다. 무엇을 시도했는지 보는 용도로만 쓴다.

- `00_기획자_초안.webp`: 기획자가 직접 만든 초안. 배치 구조만 참고하고, 비율과 위치는 다시 해석하기를 바란다.
- `재해석안_X.png`, `재해석안_Y.png`: 구조만 남기고 다시 배치해 본 두 안.

## 6. 납품 규격

| 항목 | 규격 |
| --- | --- |
| 기준 화면 | 1920×1080 (16:9) |
| 파일 형식 | PNG, 투명 배경. JPEG와 WebP는 쓰지 않는다 |
| 크기 | 가로세로 모두 4의 배수로 맞춘다 (압축 때문) |
| 여백 | 그림 둘레에 투명 여백 2픽셀 이상 |
| 글자 | 그림에 넣지 않는다. 코드로 얹는다. 글꼴은 메이플스토리 Bold / Light |
| 상태 | 버튼의 상태마다 파일 하나, 같은 크기와 같은 기준점 |
| 9분할 부품 | 모서리 크기(픽셀)를 파일 이름이나 목록에 적는다 |
| 파일 이름 | 영문. 예: `LOFT_Tab_Normal.png`, `LOFT_Tab_Selected.png`, `LOFT_Felt_9slice_48.png` |
| 원본 | 레이어가 살아 있는 원본 파일도 함께 (PSD 등) |
| 시안 | 탁자 상태와 펼침 상태를 각각 1920×1080 한 장으로 |

## 7. 진행 순서 제안

1. 위층 공방 두 상태(탁자, 펼침)의 시안을 1920×1080으로 한 장씩. 그림체 제안을 겸한다.
2. 기획자 확인 뒤 그림체와 범위 확정.
3. 4장의 부품을 낱개로 납품.
4. 같은 부품으로 역할 고르기, 이동 중, 방 만들기 화면 시안과 추가 부품.

## 9. 아직 정해지지 않은 것

- 그림체, 그리고 기존 화면을 다시 그릴지.
- 메모를 가로로 다시 뽑을지 (계획은 가로).
- 종이가 날아와 깔리는 연출의 세부. 종이 그림자나 접힌 모서리 같은 부품이 필요할 수 있다.
- 쉬움 모드에서 메모의 중요한 부분에 치는 강조 상자의 모양.
