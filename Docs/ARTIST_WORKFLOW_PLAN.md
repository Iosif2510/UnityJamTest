# 아티스트 에셋 적용·플레이 테스트 계획

기준일: 2026-11-18. **SO·프리팹 Inspector에서 에셋을 직접 연결하고, 저장한 뒤 실제 게임을 플레이하며 확인한다.** 통합 Art Workbench·전용 시각 프리뷰·폴더 자동 연결은 MVP 필수 범위에서 제외한다. 이 문서는 이전 작업창 중심 구상을 대체하는 구현 계획이며 구현 완료를 뜻하지 않는다. 초상화 제작·판정·색 처리 규칙은 [초상화 확정 계획](CUSTOMER_PORTRAIT_PLAN.md)을 유지한다.

구현 현황: 기존 선반·솥을 보존한 재료 슬롯 연결, VisualRoot/충돌 분리, 22개 인물 데이터·색 SO, 공유 PortraitView와 PortraitTest 씬, 기본 Inspector 테스트 버튼, UI Canvas 프리팹·주머니 Theme, 에셋/씬 바로가기와 고정 주문 설정을 추가했다. 실제 사용법과 검증 범위는 [아티스트 가이드](ARTIST_GUIDE.md)를 따른다. 아래 내용 중 씬 로컬 Sprite 덮어쓰기·화면 내 TestControls·상태별 바로가기는 후속 편의 기능이며, 현재는 SO 직접 연결과 Driver Inspector 버튼을 사용한다.

## 1. 기본 작업 흐름과 구현 범위

`대상 SO/프리팹 열기 → 모델·Sprite 드래그 연결 → 편집 상태에서 저장 → 누락 참조 검사 → 테스트 조건 지정 → 실제 씬에서 Play → 종료 후 원본 수정`

| 대상 | 기본 편집 위치 | 플레이 확인 |
| --- | --- | --- |
| 재료 모델 | 기존 Ingredients.asset의 prefab 참조와 게임용 재료 프리팹 VisualRoot | 선반·손·주머니·반납·솥 투입 |
| 초상화 | Customers.asset의 인물 레코드와 PortraitColors.asset | 초상화 전용 씬에서 모듈별 연결·재생, 이후 카운터에서 통합 확인 |
| UI | uGUI 프리팹의 Image/Button/Text와 RectTransform | 실제 배경·텍스트·버튼 상태·화면 크기 |
| 공용 UI 외형 | 여러 화면과 코드 생성 UI가 함께 쓰는 최소 UITheme.asset | 공유 이미지·색이 모든 사용처에 반영되는지 |

새 통합 EditorWindow, 전용 저장 시스템, 독립 프리뷰 렌더러를 먼저 만들지 않는다. 기본 Inspector·Prefab Mode·Project 검색·Unity 저장·Undo 흐름을 사용한다. 에디터 보조 기능은 대상 에셋 바로가기, 누락 검사, 고정 조건 테스트 진입에 한정한다.

아티스트는 정의된 콘텐츠에 모델·그림을 연결하고 시각 설정을 조정한다. ID·질병·레시피·잉크 규칙·인물 고정 판정 속성은 기획·프로그래머가 관리한다. 기본 Inspector 자체가 권한을 강제하지는 않으므로 필드를 그룹화·설명하고 승인된 기준표와 검사로 구분한다. 본·웨이트와 런타임 연결은 프로그래머가 먼저 준비한다.

## 2. 경로와 참조 규칙

- 경로·파일명은 파일 정리와 향후 일괄 연결의 보조 규칙이다. 런타임은 SO·프리팹의 직렬화된 Unity 오브젝트 참조를 사용하고 문자열 경로 검색으로 그림·모델을 찾지 않는다.
- 초상화는 `Assets/Arts/Portraits/<인물 ID>/POR_<인물 ID>_<레이어>.png`를 유지한다. SO 필드에 Sprite를 직접 드래그한다. 폴더 드롭만으로 자동 연결되는 기능은 후순위다.
- 재료 모델 원본은 `Assets/Arts/Ingredients/`, 게임용 재료 프리팹은 `Assets/Prefabs/Ingredients/`, UI 그림·프리팹은 각각 `Assets/Arts/UI/`, `Assets/Prefabs/UI/`로 정리한다. 실제 이행 시 기존 참조와 GUID를 보존하며 불필요한 일괄 이동은 하지 않는다.
- 같은 에셋을 교체할 때 `.meta`를 보존한다. 새 에셋을 지정하면 사용 중인 SO/프리팹 참조를 명시적으로 바꾼다. 파일명이 맞는다는 이유로 기존 참조를 자동 교체하지 않는다.
- 임포트 설정은 선택 에셋에 Inspector/Preset으로 적용한다. 프로젝트 전체에 강제 재임포트하는 자동화는 MVP 범위가 아니다.

## 3. 재료 모델 연결

```text
IngredientRoot (고정 ID·상호작용, scale 1)
├─ InteractionCollider (프로그래머가 준비하는 선택 판정)
└─ VisualRoot (아티스트가 모델·재질·로컬 변환을 수정)
```

아티스트는 기존 게임용 프리팹을 Prefab Mode로 열어 VisualRoot의 모델·재질을 교체한다. 원본 FBX를 편집하는 대신 게임용 프리팹 안에서 크기·앞 방향·중심을 맞추고 저장한다. 루트의 WarehouseIngredient·ID·상호작용 계층은 유지한다. 모델에 포함된 Collider/Rigidbody/불필요한 동작을 중복 적용하지 않도록 초기 프리팹은 프로그래머가 준비한다.

Ingredients.asset의 prefab은 이 게임용 프리팹을 참조한다. 같은 프리팹 내부의 시각 모델만 바꾸는 경우 카탈로그를 다시 연결할 필요가 없다. 프리팹 자체를 교체할 때만 해당 바리에이션 참조를 변경한다. 종류별 바리에이션은 기존 3개와 고정 ID를 유지한다.

**실제 진열 연결:** 현재 씬의 프리팹 인스턴스와 카탈로그 참조는 별도이므로, SO 참조만 바꿔도 모델이 바뀐다고 가정하지 않는다. 후속 구현에서 슬롯은 바리에이션 ID를 보관하고 카탈로그의 해당 게임용 프리팹을 생성하도록 통합한다. 기존 18개 배치 인스턴스는 슬롯 구조로 한 번 이행하고 위치는 보존한다. 이후 아티스트가 씬의 모델을 개별 교체하지 않게 한다.

손에서는 루트가 HeldItemAnchor의 위치 0·회전 0으로 붙는 현재 동작을 기준으로 VisualRoot를 맞춘다. 선반과 손에서 같은 모델 정규화로 해결되지 않을 때만 별도 표시 오프셋을 추가한다. 초기부터 다중 표시 프리셋 편집기를 만들지 않는다. Collider와 집기 거리도 실제 플레이에서 확인한다.

주머니는 현재 PocketModelDisplay의 모델 렌더링을 유지한다. icon 필드의 Sprite를 바꾸는 것으로 주머니 모델 확인을 대신하지 않는다. 현재 경로는 MeshFilter/MeshRenderer 기준이므로 SkinnedMeshRenderer 등 미지원 모델은 검사에서 알린다. 아이콘·인쇄용 그림은 기존 필드에 직접 연결하고 자동 이미지 출력은 후순위로 둔다.

## 4. 초상화 연결

새 CustomerArchetype 스키마와 실제 PortraitView를 먼저 구현한다. 기존 파츠 추첨 구조에 맞춘 임시 편집기는 만들지 않는다. 아티스트는 Customers.asset의 인물 레코드에서 BASE/EYE_CLOSED/HAIR_FRONT/HAIR_BACK Sprite를 연결하고 Inspector에서 인물별 눈 사각형 좌표와 허용 색 참조를 조정한다. 공유 색은 PortraitColors.asset에서 편집한다.

기존 확정 규칙을 유지한다. BASE/EYE_CLOSED는 필수, HAIR_FRONT는 골렘 외 필수, HAIR_BACK은 긴 머리에만 존재한다. 홍채 면은 엔진이 만들고 입·귀·송곳니는 인물 고정값이다. PNG는 1024×1536, 중앙 피벗·공통 좌표를 유지하고 trim하지 않는다. 헤어는 밝은 회색조에 단일 색을 곱한다.

초상화는 아래 전용 씬에서 인물·색을 고정해 모듈별로 연결·재생한 뒤 카운터를 플레이한다. 실제 카운터 배경·대사창 위에서 1080p 기준 높이 648px의 가독성, 홍채 누출, 감은 눈의 덮임을 확인한다. 위치를 바꾸려면 Play를 종료하고 Inspector 값을 수정·저장한 뒤 다시 실행한다. 리깅과 uGUI 어댑터가 준비되지 않은 단계는 정적 색·레이어 확인으로 기록하고 본 검수 완료로 처리하지 않는다.

HUM_M1·ELF_F2·GOL_G3의 색·깜빡임을 먼저 확인하고, 본 연동과 수인 BST_M1을 거쳐 나머지로 확장한다. 색 조합 152개의 데이터 판정 검사와 실제 화면의 대표 조합 가독성 검수는 구분한다. 전 조합 썸네일 생성·눈 영역 드래그 도구는 후순위다.

### 초상화 전용 모듈 연결·테스트 씬

초상화에 한해 `Assets/Scenes/Tests/PortraitTest.unity`를 추가할 계획이다. 아티스트는 씬을 열고 Inspector에서 모듈을 연결한 뒤 Play로 결과를 확인한다. 이 씬은 배포 빌드 목록에 넣지 않으며, 재료·일반 UI 전용 테스트 씬이나 통합 작업창으로 범위를 확대하지 않는다.

```text
PortraitTest
├─ PortraitTestDriver       인물·색 선택, 모듈별 참조·테스트 상태
├─ Camera
├─ Canvas                  실제 카운터와 같은 CanvasScaler 기준
│  ├─ Background           단색 또는 카운터 배경
│  ├─ PortraitView          게임과 공유하는 프리팹
│  │  ├─ HairBack
│  │  ├─ IrisColor
│  │  ├─ Base
│  │  ├─ EyeClosed
│  │  └─ HairFront
│  └─ TestControls          최소 재생·정지·초기화·모듈 표시 조작
└─ EventSystem
```

테스트 Driver는 실제 PortraitView와 색 적용·홍채 배치·깜빡임·본 움직임·엔딩 모듈을 참조한다. 이 모듈들의 기능 경계를 Inspector 참조와 명시적인 호출로 제공하되, 테스트를 위해 같은 렌더링 코드를 따로 작성하지 않는다. 인물별 리그는 PortraitView 내부의 실제 리그 연결 경계를 사용한다. 레이어 표시 토글은 원래 순서·본 관계를 유지하고 관련 Graphic만 제어한다.

| 모듈 | 연결할 대상 | 개별 확인 항목 |
| --- | --- | --- |
| 기본 합성 | BASE와 선택 앞·뒷머리 Sprite, 실제 레이어 참조 | 공통 좌표·순서, 레이어 단독/전체 표시, 의도적으로 없는 레이어 처리 |
| 헤어 색 | 공유 색 카탈로그, 앞·뒷머리 표시 대상 | 같은 선택 색의 곱하기 적용, 골렘의 헤어 없음 |
| 홍채 | 눈 색, 인물별 눈 사각형, 실제 단색 면 생성 모듈 | 눈 위치, 투명 구멍 채움, 외곽·입·귀로 색이 새지 않는지 |
| 깜빡임 | EYE_CLOSED, 실제 깜빡임 모듈, 조정값 | 한 번 깜빡이기, 감은 상태 유지, 자동 재생·정지, 뜬 눈의 완전한 덮임 |
| 본 움직임 | 인물 리그, 실제 본/uGUI 연동 모듈 | 호흡·고개·헤어 움직임, 홍채·감은 눈 추종, 정지·초기화 |
| 엔딩 표시 | 실제 틴트·슬라임 교체 모듈과 슬라임 Sprite | 전체 레이어 착색, 슬라임 교체, 일반 초상화 복원·인물 교체 후 잔상 |

Driver에는 Customers·PortraitColors·조정값 참조와 인물 ID·허용 색 선택을 둔다. 인물 레코드를 기본 입력으로 사용하고, 모듈을 제작 중일 때만 씬 로컬 Sprite·눈 영역 덮어쓰기 입력을 선택적으로 허용한다. 덮어쓰기 사용 여부를 명시하고 그 입력을 원본 SO에 자동 저장하지 않는다. 최종 합성 확인은 덮어쓰기를 끄고 SO 입력만으로 재현한다.

제작 중 Draft 인물도 지정해 확인할 수 있도록 질병·레시피·전체 PotionCatalog 로드에 의존하지 않는다. RoundDirector·180초 제한·주문 생성·창고 씬은 연결하지 않는다. 필요한 모듈만 실행하고, 누락된 입력은 해당 모듈의 미연결 상태로 표시한다. 예를 들어 리그가 없어도 기본 합성과 색은 확인할 수 있지만 본 재생은 사용할 수 없다. 합성·홍채·본처럼 서로 의존하는 검수는 필수 입력이 모두 연결된 경우에만 통과 처리한다.

인물·색 변경, 자동 깜빡임·본 재생, 테스트 효과는 런타임 인스턴스와 테스트 로컬 값에만 반영한다. 창작 원본을 수정할 때는 Play를 종료해 SO·프리팹을 저장한다. 씬 로컬 임시 연결이 게임 반영에 필요한 SO 저장을 대신하지 않는다. 테스트 종료·재실행 때 이전 인물·틴트·슬라임·본·타이머 상태를 초기화한다. 테스트 Driver와 조작 코드는 개발용으로 격리하고 플레이어 빌드에 포함하지 않는다.

확인 순서는 `모듈 단독 연결 → 모듈 조합 → SO 입력만으로 완성 초상화 → 실제 카운터 통합`이다. 테스트 씬에서의 엔딩 강제 재생은 표현 확인이며 실제 채점 반응의 증거가 아니다. 최종적으로 카운터 배경·대사창, 처방 복귀, 주문 교체, 판정에 따른 엔딩은 실제 게임 흐름에서 별도로 확인한다. 새 씬과 Driver 생성은 후속 구현 범위다.

## 5. UI 에셋 연결

Image의 Sprite·Color·Image Type, Button의 실제 전환 방식, Text의 폰트·크기·정렬과 RectTransform 배치는 uGUI 프리팹에서 직접 수정한다. 9-slice는 Sprite Editor의 Border와 Image 설정을 함께 맞춘다. 기존 Text를 TMP로 일괄 교체하지 않는다. 버튼 이벤트·컨트롤러·타이머 참조를 유지하면서 아트와 배치만 수정한다.

프로그램이 참조하는 UI 영역을 필요한 범위만 프리팹으로 분리하고 기존 씬의 이벤트 연결을 보존한다. 모든 화면을 새 구조로 재작성하거나 임의 프리팹 교체 인터페이스를 도입하지 않는다. 변경 전 패널·버튼·텍스트의 기존 색을 기준으로 테마를 맞춘다.

UITheme.asset은 **공유되는 이미지·색**과 PocketModelDisplay처럼 코드 생성 UI가 읽어야 하는 외형 설정에만 사용한다. 모든 Image·폰트·간격을 거대한 슬롯 목록으로 옮기지 않는다. 동일 속성을 프리팹과 Theme 양쪽에서 덮어쓰지 않도록, 공유 속성은 Theme를 적용하고 개별 속성은 프리팹 값을 쓰는 기준을 정한다. 코드에 하드코딩된 해당 색·이미지가 Theme를 읽도록 연결하는 작업은 필수다.

실제 플레이에서 버튼의 보통·가리킴·누름·선택·비활성, 짧은/긴 한국어 대사, 빈/가득 찬 주머니, 남은 시간과 결과를 확인한다. Game View에서 1920×1080·1280×720·다른 화면 비율을 선택해 CanvasScaler와 앵커의 잘림을 확인한다. 전용 상태별 프리뷰 창은 만들지 않는다.

## 6. 빠른 플레이 테스트 진입

Inspector로 편집하는 작은 **아트 테스트 설정**과 기존 카운터/창고를 여는 메뉴를 제공한다. 초상화만 위 PortraitTest 전용 씬을 추가하고, 재료·일반 UI는 기존 씬에서 확인한다. 별도 통합 작업창은 필수가 아니다. 설정에는 테스트 활성 여부, 대상 화면, 인물 ID, 허용 헤어/눈 색, 질병 또는 시드, 필요 시 재료 ID와 테스트 상태를 둔다. 새 SO 타입은 Editor 전용으로 두고 배포 콘텐츠 카탈로그에 연결하지 않는다. PortraitTest의 씬 로컬 모듈 입력과 실제 게임 고정 조건 설정은 목적과 저장 대상을 구분한다.

1. 편집 상태에서 에셋을 연결·저장하고 `Validate Catalog`로 필수 참조를 확인한다.
2. 테스트 설정을 열어 고정 조건을 선택한다. 처음에는 인물·색·시드 고정과 창고 직접 진입만 구현한다.
3. 메뉴에서 기존 `01_Order` 또는 `02_Workshop`을 연 뒤 아티스트가 Play를 누른다. 저장하지 않은 씬은 Unity의 저장 흐름으로 처리한다.
4. 테스트용 부트스트랩이 주문 생성 전에 고정 입력을 전달해 **실제 생성기·뷰·상호작용**으로 실행한다. 화면을 열 때마다 재추첨하거나 이미 생성된 주문과 그림만 따로 바꾸지 않는다.
5. 테스트를 종료하고 원본 SO/프리팹을 수정한다. 테스트를 비활성화하면 일반 게임 진입 규칙으로 돌아간다.

시드·직전 질병·고정 인물/색·콘텐츠 리비전으로 재현한다. 일치하지 않는 종족 색이나 잘못된 ID는 명확한 오류로 표시한다. 실제 플레이 중에도 테스트 실행임을 에디터에서 확인할 수 있게 한다. 원본 카탈로그의 Active 상태·시간 제한·정답 데이터를 테스트 때문에 변경하지 않는다.

처방·엔딩·결과 바로가기나 주머니 채우기는 추가 편의 기능이다. 실제 상태 전환에 필요한 값을 갖춘 테스트 부트스트랩이 준비된 상태에만 제공한다. 아직 구현되지 않은 게임 상태는 강제 진입 대상으로 표시하지 않는다. UI 패널만 켠 확인을 채점·씬 왕복 검증으로 기록하지 않는다. 플레이 진입은 사용자 조작이며 에셋 변경 때마다 자동 실행하지 않는다.

테스트 조건 소비와 부트스트랩은 Editor 전용 진입 경로로 격리한다. 런타임 표시 코드는 UnityEditor 타입을 참조하지 않고 빌드에는 테스트 설정·실행 훅이 포함되지 않도록 한다. 배포 빌드의 시작 씬·기본 생성 규칙은 유지한다.

## 7. 검사·저장·역할

- 검사는 기존 Validate Catalog를 확장해 필수 프리팹·Sprite·색 참조, 슬롯/프리팹 ID 일치, 유효한 눈 영역, 미지원 모델을 확인한다. 오류에는 해당 에셋·ID·필드와 이동 가능한 오브젝트 문맥을 제공한다. 검사가 시각 검수를 대신하지 않는다.
- 최소 메뉴는 Ingredients·Customers·색·공유 UI 설정 선택, 카운터·창고·PortraitTest 열기, 테스트 설정 선택이다. Inspector 검색과 Project 즐겨찾기를 먼저 활용한다. Find Usages/Preview Order는 기존 계획의 데이터 보조 기능이며 구현 완료로 가정하지 않는다.
- 편집 상태에서 Unity 기본 Undo·저장을 사용한다. 허브용 작업 사본·원자적 저장·커스텀 되돌리기를 추가하지 않는다. Play 중 씬 객체를 조정한 값은 종료 시 사라질 수 있고 SO·공유 에셋 편집은 남을 수 있으므로, 기본 작업은 **Play 종료 → 원본 수정·저장 → 재실행**으로 통일한다.
- 모델·Sprite 변경은 코드·슬롯·판정 ID 변경과 구분해 커밋한다. `.meta`를 함께 관리하고, 공용 재질·색을 바꿀 때는 실제 사용처를 함께 확인한다. 검사 통과만으로 Draft를 Active로 자동 전환하지 않는다.
- 아티스트는 에셋 연결·모델 시각 변환·UI 배치와 플레이 검수, 기획은 고정 속성·레시피·판정 의미와 승인, 프로그래머는 런타임 연결·프리팹 기본 구조·리깅·테스트 진입·검사 도구를 담당한다.

## 8. 구현 순서와 완료 기준

| 순서 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 기존 SO·프리팹 연결 경로와 게임 반영 | 재료 1개·초상화 1명·UI 버튼 1개를 직접 연결·저장하고 실제 씬에서 확인한다. 재실행 후 같은 에셋이 보인다. |
| 1a | PortraitTest 전용 씬·모듈별 참조와 조작 | 초상화 1명의 합성·색·홍채·깜빡임을 단독/조합으로 재생하고 SO 입력만으로 재현한다. 본은 실제 연동 완료 시 확인하며, 같은 PortraitView가 카운터에서도 동작한다. |
| 2 | 고정 조건 테스트 설정·씬 바로가기 | 특정 인물·색을 재현하고 창고에서 집기·반납·주머니를 빠르게 확인한다. 비활성화하면 일반 게임으로 돌아간다. |
| 3 | 누락 참조 검사·에셋 바로가기 | 누락·ID 불일치를 에셋 문맥과 함께 확인하고 해당 Inspector로 이동할 수 있다. |
| 4 | 전체 콘텐츠 적용과 대표 플레이 | 재료 18개·인물 22명의 연결, 화면별 UI, 본·엔딩·초기화와 씬 왕복을 실제 코드로 검수한다. |

프로젝트의 현재 Editor 사용 지침과 합의한 Play Mode 검증 범위를 따른다. 초기 계획 작성 후 구현·Play 검증을 수행했으며 현재 상태는 [아티스트 가이드](ARTIST_GUIDE.md)의 확인 결과를 따른다. 계획 항목만 보고 모든 아트 검수와 빌드가 완료됐다고 간주하지 않는다.

## 9. 반복 작업이 늘어날 때만 추가할 기능

우선순위는 폴더·파일명 기반 연결 후보 제안, 인물별 색 조합 비교, 눈 영역 시각 편집, 자료 이미지 출력 순이다. 통합 Art Workbench와 독립 프리뷰는 실제 편집 병목이 확인된 뒤 검토한다. 추가하더라도 현재 SO·프리팹 참조와 실제 표시 코드를 재사용하고 별도 콘텐츠 저장 체계를 만들지 않는다.
