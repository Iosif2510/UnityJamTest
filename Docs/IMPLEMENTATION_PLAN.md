# 시끄러운 포션공방 구현 구조 계획

이 문서는 GDD의 플레이 규칙과 부스 시연 조건을 바탕으로, 현재 Unity 프로젝트에 적용할 구조를 정한다. 구현의 기준은 **제조자 한 명이 PC를 조작하고 해설자 한 명이 종이 자료를 보며, 손님 한 명을 180초 안에 응대하는 한 판**이다. 씬 분할, 코드 책임, 데이터 형식, 구현 우선순위는 프로젝트의 현재 상태와 24시간 제작 일정을 기준으로 정했다.

손님 초상화는 2026-11-18 업데이트 작업지시서를 우선한 [손님 초상화 구성 시스템 확정 계획](CUSTOMER_PORTRAIT_PLAN.md)을 따른다. 22명 고정 인물에 헤어·눈 색만 조합하고, 성별·귀·송곳니·직업은 인물 속성으로 둔다. 아래 초상화 관련 항목은 이 기준으로 갱신했으며, 실제 코드·에셋 이행은 후속 구현 범위다.

아티스트의 모델·초상화·UI 적용은 [아티스트 에셋 적용·플레이 테스트 계획](ARTIST_WORKFLOW_PLAN.md)에 따라 SO·프리팹 Inspector 직접 연결과 실제 플레이 확인을 우선한다. 런타임 반영 경로, 고정 조건 테스트 진입, 누락 검사·에셋 바로가기를 먼저 만들고 통합 작업창·전용 시각 프리뷰는 후순위로 둔다.

## 씬 구성

런타임 씬은 **카운터와 창고 두 개**로 운용한다. 대기·접객·처방·엔딩·결과는 같은 배경과 손님을 쓰므로 카운터 안에서 패널을 바꾼다. 창고는 1인칭 카메라, 커서 잠금, 이동 입력과 공간 배치가 따로 필요하므로 씬으로 분리한다. 전환 시엔 Single 로드로 이전 씬의 UI와 입력을 함께 정리한다.

개발용으로 초상화만 `Assets/Scenes/Tests/PortraitTest.unity`를 별도 구성한다. 실제 PortraitView 프리팹과 합성·색·홍채·깜빡임·본·엔딩 모듈의 참조를 연결하고, RoundDirector나 전체 카탈로그 없이 Play로 개별/조합 테스트한다. 배포 빌드 목록에서는 제외하며 최종 카운터 통합 검수는 유지한다. 씬 계층과 입력·저장 규칙은 [아티스트 계획](ARTIST_WORKFLOW_PLAN.md)의 초상화 전용 씬 항목을 따른다. 재료·일반 UI는 기존 씬 테스트 방식을 유지한다.

게임잼 중에는 기존 씬 파일명과 GUID를 유지한다. 아래 이름은 각 씬의 역할을 뜻한다.

| 씬 역할 | 현재 에셋 | 변경 사항 |
| --- | --- | --- |
| 카운터 | `Assets/Scenes/01_Order.unity` | 첫 빌드 씬으로 지정한다. 손님 초상화를 접객과 처방에서 공유하고, 대기·엔딩·결과 패널을 추가한다. |
| 창고 | `Assets/Scenes/02_Workshop.unity` | 이미 연결된 FirstPersonController, Cinemachine, 입력 참조와 바닥을 재사용한다. 선반과 솥에 상호작용을 연결한다. |
| 기존 타이틀 | `Assets/Scenes/00_Title.unity` | 시작 버튼의 역할을 카운터 대기 화면으로 옮기고 빌드 목록에서 제외한다. 파일은 보존한다. |

```text
카운터 (01_Order)
├─ RoundRoot [RoundDirector, 카탈로그·조정값 참조]  ← 씬 사이에 유지
├─ CounterView [현재 단계에 따라 패널 전환]
│  ├─ Shared [배경, 초상화, 남은 시간]
│  ├─ WaitingPanel [커튼, 손님 받기]
│  ├─ ConsultPanel [대사, 창고로]
│  ├─ PrescribePanel [병, 잉크, 건네기]
│  ├─ EndingPanel [반응 대사·연출]
│  └─ ResultPanel [항목별 결과, 시간, 점수, 도장, 확인]
├─ Camera
└─ EventSystem

창고 (02_Workshop)
├─ StorageView [씬 참조, 창고 입력 활성화·종료]
├─ Player [기존 FirstPersonController, StorageInteractor]
│  ├─ CameraTarget
│  └─ HeldItemAnchor
├─ PlayerCamera 및 기존 Cinemachine 리그
├─ Environment [바닥, 선반 슬롯, 솥]
└─ UI [프롬프트, 주머니 3칸, 남은 시간, 종이 자료 교체 안내]
```

기존 `SceneFlow.LoadNextScene()`에 연결된 버튼은 단계별 동작으로 다시 연결한다. 예를 들어 **창고로**는 로드 자체를 실행하기 전에 접객 상태인지 확인하고, **건네기**는 병과 잉크 선택을 제출한다. 기존 공방의 **Preview result**는 실제 제출 경로가 연결되면 제거한다.

## 한 판의 상태와 시간

`Waiting → Consult → Storage → Prescribe → Ending → Result → Waiting`

| 전환 | 조건과 처리 |
| --- | --- |
| 대기 → 접객 | **손님 받기**를 누르면 주문을 한 번 생성한다. 커튼 연출 뒤 손님이 처음 표시될 때 180초 마감 시각을 설정한다. |
| 접객 → 창고 | 대사 출력이 끝나면 **창고로**를 켠다. 출력된 대사는 화면에 남긴다. 버튼을 누르면 창고를 로드한다. |
| 창고 → 처방 | 솥을 누르면 주머니의 재료 ID를 복사해 투입을 확정한다. 창고 입력을 멈추고 종이 자료 교체 안내를 보여준 뒤 약 4초 후 카운터를 연다. 카운터는 현재 판의 처방을 표시한다. |
| 처방 → 엔딩 | 병과 잉크가 둘 다 선택됐고 제한 시간이 남아 있을 때만 건네기를 수락한다. 시계를 멈추고 판정 결과를 한 번 만든다. |
| 엔딩 → 결과 → 대기 | 손님 반응과 퇴장 뒤 결과를 표시한다. **확인**을 누르면 현재 판의 입력과 결과를 비우고 닫힌 커튼으로 돌아간다. 이전 질병 ID만 다음 추첨에 사용한다. |

- **시간의 기준은 하나다.** `RoundDirector`가 게임 속도와 독립적인 시계로 마감 시각을 관리한다. 창고 로드, 솥 대기, 카운터 복귀 시간도 포함한다. 각 UI는 같은 남은 시간을 읽는다.
- **공방에서 시간이 끝나면** 집기와 투입을 막고 카운터로 돌아가 시간 초과 퇴장과 0점 결과를 보여준다. 씬 로드 중이면 진행 중인 로드가 끝난 뒤 목적지를 정리한다. 뒤늦게 끝난 솥 연출이 처방을 열지 않도록 전환 시 현재 상태를 다시 확인한다.
- **마감과 제출이 겹치면** 건네기를 처리하는 순간의 시각으로 판정한다. 마감에 도달했으면 시간 초과다. 제출이나 시간 초과를 확정한 뒤에는 추가 입력을 받지 않는다.

## 코드와 데이터 책임

| 구성 | 책임 |
| --- | --- |
| `RoundDirector` | 씬 사이에 유지되는 유일한 MonoBehaviour. 현재 단계, 마감 시각, 씬 로드, 제출 확정과 다음 판 초기화를 담당한다. 새 카운터가 로드될 때 기존 인스턴스가 있으면 새 루트를 정리한다. |
| `RoundState` | 일반 C# 객체로 현재 판의 상태를 묶는다. 생성 시 확정한 손님·대사·레시피·정답 병·정답 잉크와, 플레이 도중 들어온 제출값·결과를 구분한다. 씬 오브젝트를 보관하지 않는다. |
| `OrderGenerator` | 종족·고정 인물·허용 헤어/눈 색과 질병을 뽑고, 고정 외형 속성으로 정답을 만든다. 인물·질병 전용 대사가 없으면 질병 공통 대사를 선택한다. 생성은 판 시작 때 한 번만 한다. |
| `CounterView` (현재 `OrderSceneView`) | 화면 상태를 표시하고 버튼 의도를 전달한다. 공유 `PortraitView`에 생성된 인물·색을 전달하고 대사를 출력한다. 병·잉크 선택이 끝났는지는 화면에서 표시하고, 제출 가능 여부는 `RoundDirector`에서 확정한다. |
| `PortraitView` | 뒷머리 → 엔진 생성 홍채 면 → 베이스 → 감은 눈 → 앞머리를 조립한다. 헤어 색 곱하기, 깜빡임, 본 추종과 엔딩 표시·초기화를 담당한다. |
| `StorageView`, `StorageInteractor` | 창고 선반 6개, 주머니, 솥을 연결한다. 상호작용과 재료를 든 상태는 창고에 두고, 솥 투입이 확정된 재료 ID만 현재 판에 넘긴다. |
| `RoundJudge` | 정답과 제출값을 받아 재료별 결과, 병·잉크 정오, 점수, 도장과 반응 유형을 반환하는 일반 C# 함수다. 결과 UI와 엔딩 연출은 이 결과를 공통으로 사용한다. |

`PotionCatalog` ScriptableObject는 씬에서 참조하는 단일 진입점으로 두고, 실제 목록은 손님·질병과 레시피·재료·처방 규칙 에셋으로 나눈다. 시간·거리·점수는 `RoundTuning`에서 관리한다. 플레이 중 뽑힌 주문과 선택값은 카탈로그에 쓰지 않는다. 추가·수정·제외와 데이터 검사 절차는 [인게임 데이터 파이프라인 계획](DATA_PIPELINE_PLAN.md)을 따른다.

| 카탈로그 항목 | 최소 필드 |
| --- | --- |
| 손님 외형 | 22개 고정 인물의 호출코드·종족·성별·직업·귀 유형·송곳니, 베이스·감은 눈·앞/뒷머리 Sprite, 허용 헤어/눈 색 ID, 인물별 홍채 영역과 리그. 입·귀를 별도 Sprite로 추첨하지 않는다. |
| 초상화 색 | 색 ID·표시 이름·단일 색 값. 밝은 회색조 헤어에 곱하고, 엔진 생성 홍채 면에 지정한다. 골렘은 헤어가 없다. |
| 질병과 레시피 | 질병 ID, 대사 후보 및 증상 구간, 레시피 참조. 레시피는 종이 자료에 표시할 포션명과 서로 다른 재료 종류에서 하나씩 고른 바리에이션 ID 3개를 가진다. |
| 재료 | 종류 ID와 종류별 바리에이션 3개. 각 바리에이션은 고정 ID, 프리팹, 주머니 아이콘을 가진다. 채점은 바리에이션 ID로 한다. |
| 병·잉크 | 성별별 병 매핑, 잉크 규칙의 순서·조건·예외·결과. 처음 맞는 규칙을 쓰며 마지막 줄은 기본값이다. |
| 반응 | 병·잉크 오답, 재료 오답 수, 시간 초과에 해당하는 대사와 표시할 효과. |

잉크 조건에는 이번 콘텐츠에서 필요한 속성 비교, AND, 예외만 넣는다. 고정 성별·귀·송곳니와 선택 헤어/눈 색 ID를 사용하며, 스프라이트 이름이나 RGB에서 추론하지 않는다. 같은 생성값으로 초상화를 표시하고 정답도 결정한다. 직업은 대사 작성 문맥에 사용하되 질병·정답은 외형과 독립적이다. 진단 단계에서는 병명을 입력받지 않는다. 둘이 해석한 결과는 창고에서 고른 재료에 반영된다.

## 상호작용과 채점 세부 결정

- **재료는 선반 → 손 → 주머니 순서로 이동한다.** 선반을 보며 좌클릭하면 한 개를 집어 기존 HeldItemAnchor에 표시한다. 우클릭으로 원래 선반에 돌려놓고, F로 확정해 주머니에 넣는다. 주머니에 들어간 재료는 이번 판에 꺼낼 수 없다. 게임 화면에는 재료 이름을 표시하지 않는다.
- **재료 규칙 확정**. 모든 주문의 레시피에는 서로 다른 종류 3개가 들어가고, 종류마다 바리에이션이 정확히 3개다. 창고에는 서로 다른 종류의 선반 6개가 있고 선반마다 해당 종류의 바리에이션 3개를 진열한다. 주머니는 3칸이며 다 차면 추가 입고를 막는다. 정답 종류나 맞힌 개수는 제출 전까지 표시하지 않는다. 솥 상호작용과 안내선은 개수만 확인한다.
- **솥 안내선**은 먼저 고정된 방에서 미리 배치한 경유점과 바닥 선으로 구현할 수 있는지 본다. 통로가 바뀌는 레벨이 확정되면 그때 동적 경로를 검토한다. 재료 배치 섞기는 슬롯 위치를 고정하고 각 슬롯에 놓이는 재료만 바꾼다.
- **채점**은 정답 재료와 제출 재료를 순서 없이 일대일로 맞춘다. 같은 재료 ID를 여러 번 맞힌 것으로 세지 않는다. 초기 점수는 재료 총 60점, 병·잉크 각 20점, 남은 10초마다 5점이다. 정답 재료 하나당 20점을 준다. 시간 초과는 보너스를 포함해 0점으로 확정한다.
- **처방 UI 입력**은 카운터로 돌아올 때 커서를 풀고 창고 입력을 끈 상태로 시작한다. 병과 잉크 셀렉션의 강조 표시와 건네기 버튼이 같은 선택값을 사용한다.

## 24시간 구현 순서

| 경과 | 작업 | 다음 작업으로 넘어가는 기준 |
| --- | --- | --- |
| 0–4시간 | 기존 두 씬에 카운터·창고 역할 부여. `RoundDirector`, 임시 데이터, 상태별 패널과 시간 초과 경로 연결. | 임시 버튼으로도 한 판을 제출하고 결과에서 다음 팀 대기로 돌아갈 수 있다. |
| 4–10시간 | 창고 입력과 선반·주머니·솥 연결. 6개 선반에 6종 × 3개 바리에이션을 진열. | 재료 3개를 골라 솥에 넣고, 그 선택이 카운터까지 전달된다. |
| 10–15시간 | 손님·질병 생성, 대사와 초상화, 병·잉크 선택, 판정 및 결과 연결. | 서로 다른 레시피와 외형이 실제로 다른 정답을 만들고, 엔딩과 점수에 동일한 판정이 쓰인다. |
| 15–20시간 | 아트와 종이 자료 통합. 재료 슬롯 섞기, 솥 안내, 커튼·반응 연출 순으로 추가. | 질병 카드에서 제조법을 찾을 수 있고, 종이의 재료 그림과 게임 모델 및 잉크 조건이 일치한다. |
| 20–24시간 | 시연 빌드와 수정 여유 확보. | 배포 빌드가 닫힌 커튼에서 시작하며, 결과 확인으로 다음 팀을 받을 수 있다. |

프로그래밍은 **질병 2종, 종류별 정답 바리에이션이 다른 3종 레시피 2개, 병과 잉크가 달라지는 손님 외형**으로 흐름을 먼저 연결한다. 제작 초반에 기획과 포션명·증상·외형 속성·재료 ID를 맞추고, 아트에는 초상화 공통 캔버스와 선반 슬롯 기준을 전달한다. 시연용 분량이 밀리면 질병을 구별 증상이 있는 2쌍으로 줄이고, 추가 대사와 고급 연출은 뒤로 미룬다. 종이 자료도 실제 빌드에 들어간 질병과 레시피 수에 맞춘다.

초상화 제작은 HUM_M1·ELF_F2·GOL_G3의 색 교체와 깜빡임을 먼저 승인하고, 본 변형과 수인 BST_M1의 판정 요소를 확인한 뒤 나머지 인물로 확장한다. Unity 2D Animation과 uGUI 연결은 별도 구현 항목이며 정적 조립 성공으로 본 작업을 완료 처리하지 않는다. 세부 도입 순서와 검수 범위는 초상화 계획을 따른다.

구조 작업의 완료 확인은 씬 저장, 빌드 목록, Inspector 참조 확인으로 제한한다. 반복 Play Mode 검사나 별도 검증 도구가 필요해지면 확인하려는 위험과 범위를 먼저 공유하고 진행 여부를 묻는다.
