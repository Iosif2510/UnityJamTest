# 주문·완료 다이얼로그 표시 구현 계획

주문·수령·복용 후 대사는 손님마다 작성한다. 같은 질병이나 판정 결과라도 손님의 직업과 말투가 대사에 드러나게 하고, 대사마다 본문 폰트와 증상 구간 연출을 지정한다. 표시 타이밍과 효과는 [HTML 대사 뷰어](../tmp/대사보기_시끄러운포션공방.html), 라운드 상태와 마감은 [게임 구현 구조 계획](IMPLEMENTATION_PLAN.md)을 기준으로 한다.

## 1. 화면과 진행

| 단계 | 표시와 입력 |
| --- | --- |
| 접객 `Consult` | 기존 판에서 뽑은 손님, 초상화, `DialogueOption`을 사용한다. 이름표는 HTML과 같은 ‘손님’을 사용한다. 대사가 끝나면 **창고로**를 활성화하고, 이동할 때까지 본문을 유지한다. 접객 대사 표시 시간은 현재 180초 제한에 포함한다. |
| 처방 `Prescribe` | 동일한 카운터에서 병과 잉크 선택을 표시한다. 기한 내 **건네기**를 수락하는 순간 남은 시간을 확정하고, 기존 채점으로 `RoundResult`를 한 번 생성한 뒤 `Ending`으로 전환한다. |
| 완료 `Ending` | 같은 손님과 대사창으로 ‘받을 때’를 재생한다. 재생 완료 시점부터 1.5초 동안 첫 대사를 보여 준 뒤 ‘마신 후’로 교체한다. 마지막 대사가 끝나면 본문을 유지하고 **결과 보기**를 활성화한다. |
| 결과 `Result` | **결과 보기**를 누르면 초상화와 대사창을 닫고 기존 점수판을 표시한다. 기존 다음 주문 버튼으로 새 손님을 받는다. |
| 시간 초과 | `Consult`·`Storage`·`Prescribe`에서 현재 재생과 대기를 취소하고 기존 0점 결과 경로로 전환한다. 창고에서는 카운터 복귀를 거쳐 결과를 표시한다. |

재생 중 대사창 입력을 받으면 현재 대사만 즉시 완성한다. 이 입력도 정상 완료와 같은 경로를 타므로 첫 완료 대사를 즉시 표시해도 1.5초 간격이 시작되고, 결과 확인은 별도 버튼 입력으로 진행된다.

## 2. HTML에서 옮길 표시 규칙

- **어절 공개.** 본문 전체를 처음에 배치하고, 기본 평균 **23자/초**로 앞에서부터 어절을 공개한다. 공백과 문장부호를 포함한 본문 길이를 23으로 나누어 전체 재생 시간을 얻는다. HTML의 가중치는 어절당 `0.9 + 한글·영문·숫자 수 × 1.0`, 증상이 섞인 어절은 읽기 가중치 `× 1.25`다. 어절 말미 쉼표 `1.3`, 마침표·물음표·느낌표 `2.4`, 말줄임 `3.2`를 휴지 가중치로 더하고 총시간에 맞춰 비례 환산한다. 어절은 시작 시점에 한꺼번에 나타나며 **0.16초** 동안 페이드 인한다. 최종 어절이 보이는 시점과 전체 재생 완료 시점은 구분한다.
- **레이아웃.** `OrderCanvas`의 기존 `DialoguePanel` 위치와 어두운 패널·밝은 글자 팔레트를 기준으로 이름표와 본문을 배치한다. 1280×720 기준 Canvas에서 본문은 어절 단위 줄바꿈을 우선하고 폭보다 긴 어절만 글자 단위로 줄바꿈한다. 패널 최대 높이에서 넘치는 본문은 세로 스크롤로 읽고, 재생 중 최신 공개 글자가 가려질 때만 스크롤을 내린다. 각 대사의 스크롤 시작 위치는 맨 위다.
- **초기 설정.** 재생 속도, 페이드 시간, 반응 간격은 Inspector에서 조정할 수 있게 한다. 어절을 게임 기본 모드로 두고, HTML에서 제공하는 문장·글자 모드는 같은 타임라인의 비교 옵션으로 검증한다.

## 3. 손님별 대사와 폰트

### 대사 선택

| 시점 | 전용 대사 키 | 전용 대사 미작성 시 | 저장 위치 |
| --- | --- | --- | --- |
| 주문 | `(customerId, diseaseId)` | 해당 질병의 공통 대사 | `DiseasesAndRecipes.asset`의 기존 `CustomerDialogueOverride` |
| 받을 때 | `(customerId, rcv_* 반응)` | 같은 수령 반응의 공통 대사 | `PrescriptionRules.asset`의 `ReactionDialogue` |
| 마신 후 | `(customerId, aft_* 반응)` | 같은 복용 후 반응의 공통 대사 | `PrescriptionRules.asset`의 `ReactionDialogue` |

`HUM_M1`, `ELF_M1`처럼 `Customers.asset`의 고정 호출코드로 연결한다. 주문은 기존 `OrderGenerator`가 전용 후보를 우선해 `GeneratedOrder.Dialogue`에 확정한다. 제출 시에는 같은 `CurrentOrder.Customer.Id`와 확정된 `RoundResult`로 반응 두 개를 고른 뒤 해당 대사를 한 번씩 결정한다. 후보가 여러 개면 판 시드를 기준으로 선택하고, 재생·건너뛰기·씬 왕복에서는 확정된 후보를 사용한다.

공통 대사는 콘텐츠 작성 중 기본 대사로 활용한다. 최종 검수에서는 활성 손님과 질병·반응의 조합마다 손님 전용 후보가 하나 이상 있는지 확인한다. 현재 22명·활성 질병 4종 기준으로 주문 88조합, 수령·복용 후 176조합이다. 같은 질병의 전용 대사는 말투와 상황을 바꾸더라도 종이 카드가 가리키는 증상 단서를 담는다. 완료 대사는 선택된 판정에 맞는 말투와 내용으로 작성한다.

### Inspector의 폰트 지정

| 설정 위치 | 설정과 적용 범위 |
| --- | --- |
| `DialogueOption.font` | 선택된 대사 후보의 본문 전체에 적용할 `TMP_FontAsset`. 같은 손님의 주문·수령·복용 후에 각각 다른 값을 지정할 수 있다. 빈 값은 손님 기본값을 사용한다. |
| `CustomerProfile.defaultDialogueFont` | 손님 말투에 대응하는 기본 `TMP_FontAsset`. 공통 대사로 재생할 때도 대사 후보의 폰트 필드가 비어 있으면 적용된다. 빈 값은 대사창 기본값을 사용한다. |
| `DialogueView.defaultBodyFont` | 대사창 기본 한국어 `TMP_FontAsset`. HTML 기본인 마루 부리를 첫 후보로 두고 원본 라이선스와 배포용 폰트 파일을 확인한다. 이름표 ‘손님’에는 별도의 고정 UI 폰트를 연결한다. |

손님별 기본 서체는 `Customers.asset`에서 한 번 지정하고, 개별 대사의 서체는 대사 후보에서 바꾼다. 공통 대사 후보는 폰트를 비워 호출한 손님의 서체를 따르게 한다. 같은 서체를 쓰는 후보들은 하나의 폰트 에셋을 공유한다. 배포용 정적 SDF는 선택된 대사 원문과 이름표, 문장부호 및 되울림에 쓰는 `…`의 글리프를 포함한다. 빠진 글리프는 해당 에셋의 한국어 대체 폰트 목록에서 찾고, `Validate Catalog`에서 대체 체인까지 검사한다.

재생 요청이 들어오면 확정된 폰트와 그 폰트의 머티리얼을 먼저 적용한다. 그 뒤 전체 본문의 줄바꿈과 메시를 계산하고 숨겨 둔 글자를 공개한다. 재생 도중에는 같은 서체와 크기를 유지하며, ‘받을 때’에서 ‘마신 후’로 교체할 때 새 후보의 폰트로 본문 배치를 다시 만든다.

## 4. 증상 구간별 효과

| 설정 위치 | 설정과 적용 범위 |
| --- | --- |
| `DialogueSegment.isSymptom` | HTML `<sym>`과 같은 구간 표시. 주문에서는 해당 구간이 포함된 어절에 증상 읽기 가중치를 적용한다. 일반 구간과 공백은 기본 상태로 렌더링한다. |
| `DialogueSegment.effect` | 증상 구간의 `Inherit`, `None`, 또는 아래 6개 효과. `Inherit`은 대사 후보의 기본값을 사용하고, `None`은 해당 구간의 시각 효과를 끈다. 하나의 대사에서 구간별로 다른 효과를 고를 수 있다. |
| `DialogueOption.defaultSymptomEffect` | 이 대사의 `Inherit` 증상 구간에 적용할 기본 효과. 명시적인 `None`을 지정할 수 있다. `Inherit`이면 주문에서는 질병 기본 효과를 사용하고, 완료 대사에서는 `None`으로 해석한다. |
| `DiseaseEntry.defaultSymptomEffect` | 주문 대사의 기본 효과. 현재 활성 질병 4종은 HTML의 6종과 구성이 달라 우선 `disease.shadow_lag`에 그림자 늑장을 명시하고, 나머지는 기본 `None`으로 시작한다. |

`IsSymptom`은 증상 단서 표시이고 `effect`는 시각 연출 선택이다. `IsSymptom = true`인 주문 구간에 `None`을 지정해도 증상 어절의 읽기 가중치는 적용된다. 완료 대사에도 시각 효과가 필요한 경우 후보와 증상 구간에 직접 지정하며, 읽기 속도는 일반 완료 대사와 동일한 규칙으로 계산한다.

| HTML 증상 효과 | Unity에서 재현할 동작 |
| --- | --- |
| `DIS_01` 그림자 늑장 | 본문 위치는 고정한다. 그림자가 1.6초에 걸쳐 따라붙고 3.4초 주기로 어긋나거나 흐려진다. |
| `DIS_02` 되울림 | 글자 잔상이 1.8초 주기로 오른쪽으로 번진다. 증상 구간 마지막 어절의 끝 두 글자를 따서 만든 작은 ‘…두 글자’ 잔상은 2.6초 동안 밝기가 오르내린 뒤 흐리게 남는다. 잔상의 표시 공간은 처음에 확보한다. |
| `DIS_03` 들뜸 | 해당 글자가 3.2초 주기로 위로 떠오르고 옆으로 살짝 밀린다. |
| `DIS_04` 거울잠 | 글자 뒤에 좌우 반전된 잔상을 놓고 3.4초 주기로 꾸벅이는 움직임을 준다. |
| `DIS_05` 빗물 | 글자 아래에 작은 물방울이 2.8초 주기로 맺혔다 떨어진다. |
| `DIS_06` 서리 | 해당 글자가 1.4초에 걸쳐 서리색으로 변하고 0.22초 주기로 가볍게 떨린다. |

### 재생 준비와 적용

1. **문자 범위 작성.** 세그먼트의 공백을 보존해 TMP 본문과 각 구간의 시작·끝 문자 범위를 한 번 만든다. 각 증상 구간의 최종 효과를 확정하고, 전체 본문에서 어절 경계를 계산한다. 하나의 어절이 세그먼트 경계를 걸쳐도 공개는 어절 단위로, 효과는 해당 구간의 글자에만 적용된다.
2. **글리프 연결.** 확정된 폰트로 본문 레이아웃을 만든 뒤 원문 문자 위치를 TMP 글리프, 메시 인덱스, 꼭짓점 범위에 연결한다. 대체 폰트 글리프가 사용하는 별도 메시도 포함한다. 되울림의 ‘…두 글자’는 구간 끝에 미리 공간을 잡고 마지막 증상 글자가 공개되면 표시한다.
3. **공개와 연출 합성.** 어절이 공개된 시각을 글자 효과의 시작점으로 삼고 HTML의 글자별 위상차와 반복 주기를 적용한다. 각 프레임에 원본 메시 좌표·색을 기준으로 페이드와 효과를 합성한다. 그림자·물방울·거울상은 공개된 글리프 좌표를 기준으로 배치한다. 화면 크기가 변해 줄바꿈이 다시 계산되면 현재 재생 시각을 유지한 채 글리프 연결을 갱신한다.
4. **교체와 정리.** 현재 대사를 즉시 표시하면 나머지 글자를 전부 공개하고 그 글자들의 효과를 시작한다. 완료된 대사를 읽는 동안 반복 효과는 계속된다. 다음 대사나 화면으로 전환할 때 기존 효과와 잔상, 스크롤 위치를 정리한다.

## 5. 런타임과 데이터 변경

1. **대사창과 타임라인.** `OrderCanvas.prefab`의 `DialoguePanel`에 이름표, `ScrollRect` 뷰포트, TMP 본문을 구성하고 `01_Order`의 `OrderSceneView` 참조를 다시 연결한다. 일반 C# `DialogueTimeline`이 공개 범위와 시각을 계산하고, `DialogueView`가 폰트 적용과 UniTask 기반 비스케일 재생·완료·취소를 제어한다. 어절 페이드에는 LitMotion을 사용하며, 별도 증상 효과 컴포넌트가 글리프 효과와 잔상·물방울을 처리한다.
2. **접객 연결.** `OrderSceneView`가 `Consult` 진입 시 현재 주문의 대사를 한 번 시작한다. 같은 주문과 단계가 유지될 때만 완료 이벤트로 **창고로**를 활성화한다. `Prescribe`에서는 선택 UI를, `Consult`와 `Ending`에서는 공용 대사창을 사용한다.
3. **완료 연결.** `RoundDirector`에 `Ending`과 완료 전환 진입점을 추가한다. `TryServe()`가 마감을 먼저 확인한 뒤 판정을 확정하며, `Ending`에는 제한 시간이 흐르지 않는다. `OrderSceneView`가 두 대사와 `RoundTuning`의 `reactionGap`을 순서대로 재생한다. ‘마신 후’의 변색·슬라임 표현은 각각 기존 `PortraitView.Tint()`와 `PortraitView.ShowSlime()`에 연결한다. 현재 `Customers.asset`의 슬라임 Sprite가 비어 있으므로, 참조가 없는 상태에서도 대사와 점수판까지 진행되도록 하고 아트 연결 후 변신을 검수한다.
4. **반응 데이터 이행.** `ReactionDialogue`에 선택적인 `customerId`와 `DialogueOption` 후보 목록을 추가한다. `customerId`가 비어 있으면 공통 항목이다. 기존 `ReactionKind`의 직렬화 값 0~5를 보존하면서 빠진 반응 값만 추가한다. 기존 문자열 목록은 일반 구간 하나를 가진 후보로 이행하고, HTML의 `rcv_*`·`aft_*` 8줄을 새 공통 목록에 채운다. 기존 시간 초과 항목의 값과 문구도 데이터 이행에서 보존한다. 기존 `DialogueSegment`에 추가하는 `effect`는 기본 `Inherit`로 두어 기존 본문과 증상 범위를 그대로 읽는다.
5. **카탈로그 검사.** 기존 `Validate Catalog`에서 주문 및 완료 전용 대사의 ID 참조, 키 중복, 빈 후보, 폰트 글리프, 일반 구간의 효과 지정, 주문 대사의 증상 구간 누락을 확인한다. 콘텐츠 편집 중에는 공통 대사로 대체된 조합을 목록으로 표시한다. 배포 전에는 손님별 전용 후보의 적용 범위를 확인한다.
6. **재생 수명.** 새 대사, 단계 전환, 오브젝트 비활성화·파괴에서 진행 중인 UniTask와 LitMotion을 정리한다. 주문과 단계가 바뀐 뒤 이전 재생의 완료 콜백이 버튼을 켜거나 결과를 열지 않도록 확인한다. 대사 상태와 효과 핸들은 인스턴스에만 보관한다.

## 6. 구현 순서와 완료 기준

| 순서 | 검증할 결과 |
| --- | --- |
| 1. 손님별 주문과 폰트 | 동일 질병을 고정한 두 손님으로 전용 대사와 폰트 선택을 검증한다. 전용 대사가 없을 때는 질병 공통 대사에 손님 기본 폰트가 적용된다. 1280×720, 1920×1080 및 좁은 화면에서 두 폰트의 긴 한글 대사, 대체 글리프, 줄바꿈과 자동 스크롤을 확인한다. |
| 2. 증상 구간과 재생 | HTML 주문 샘플 6줄은 189~206자이고 기본 설정에서 약 8.22~8.96초에 끝난다. 6종 효과의 위상과 반복 주기, 한 대사의 서로 다른 구간에 지정한 효과, `None` 처리, 글리프 대체 폰트, 어절 중간의 증상 경계, 되울림 잔상 위치를 확인한다. |
| 3. 손님별 완료와 반복 플레이 | 병·잉크 정오 4조합 × 재료 정답 수 4가지로 두 반응 키를 확인한다. 두 손님에게 동일 결과를 주었을 때 손님별 후보가 표시되고, 첫 대사 완료 후 1.5초에 둘째 대사 및 해당 폰트로 교체된다. 연속 제출과 마감 직전 입력에서 점수는 한 번만 확정된다. 창고 왕복, 화면 비활성화, 즉시 표시, Play Mode 재진입에서 이전 글리프 효과와 폰트가 남지 않는지 확인한다. 슬라임 Sprite 연결 전후 모두 결과로 진행된다. |
