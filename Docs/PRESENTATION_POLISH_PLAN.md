# 주문·작업실 연출 개선 구현 계획

대사 효과를 먼저 강화한다. 증상 또는 감정을 담은 어절이 움직임과 색으로 바로 구분되어야 하며, 같은 화면에서 손님 동작과 배경 조명이 움직여도 본문을 읽을 수 있어야 한다. 이어서 입장·변신·결과 연출을 연결하고, 작업실에서 손의 재료가 주머니를 거쳐 가마솥에 들어가는 과정을 보여 준다.

## 1. 대사와 HUD

| 요청 | 구현 | 완료 기준 |
| --- | --- | --- |
| **1. 타이머** | `OrderCanvas/RoundTimer`의 앵커를 오른쪽 위에서 중앙 위로 옮기고, 기준 폭을 110에서 220으로 늘린다. 실제로 보이는 숫자의 가로 길이도 약 2배가 되도록 폰트 크기와 행 높이를 맞춘다. 첫 `Consult` 프레임부터 표시하며, 중앙 피벗을 기준으로 시계·반시계 방향으로 `±2°`, 한 왕복 2.0초의 부드러운 회전을 적용한다. 이미 중앙 위에 있는 작업실 타이머에는 현재 프레임을 활용해 동일한 회전을 적용한다. | 첫 손님 상담부터 카운트다운이 보이고, 작업실 왕복 후에도 남은 시간이 이어진다. 회전 중 타이머가 화면 가장자리나 입장 문구와 겹치지 않는다. |
| **2. 위도우 방지** | 주문·수령·복용 본문을 공백과 문장 끝 구두점 뒤에서 줄바꿈한다. 마침표·말줄임표·닫는 따옴표는 앞 어절에 붙이고 숫자의 소수점은 어절 내부로 취급한다. 문단 마지막에 한 글자만 남으면 이전 어절과 묶을 수 있는지 확인해 함께 다음 줄로 넘긴다. 가용 폭보다 긴 단일 어절만 표시 가능한 글자 경계에서 나눈다. | 한글 조사나 마침표 하나만 다음 줄에 남는 사례가 해소된다. 긴 API 대사, 고정 대사, 의도적으로 삽입한 개행이 모두 표시된다. |
| **3. 창고로 버튼** | 현재 버튼의 배경색 계열에서 밝은 톤을 잡고, 라벨은 기존 팔레트의 짙은 색으로 조정한다. 접객 대사 완료 또는 스킵 직후 활성화부터 배경 밝기만 약 1.6초 주기로 부드럽게 점멸시킨다. 누르거나 화면을 이동하면 점멸을 종료한다. | 활성화된 **창고로**가 눈에 띄고 라벨 대비가 점멸 전 구간에서 유지된다. 같은 버튼이 **결과 보기**로 쓰이는 구간에는 해당 점멸이 적용되지 않는다. |
| **4. 텍스트 효과 강화** | `DialogueTimeline`과 `DialogueGlyphLayer`의 여섯 증상 효과를 재사용한다. 첫 조정은 이동·회전·잔상의 가시 강도 1.5배, 핵심 구간의 또렷한 효과 0.45~0.7초로 잡고 효과별로 조정한다. 주문 대사는 한 줄에 최소 두 번의 강조를 목표로 하고, 같은 증상 구간에 강조가 몰리면 문장 내에서 시차를 둔다. 효과를 지정한 증상 구간을 우선 사용하고 부족한 경우 읽을 단어의 등장에 짧은 크기 변화를 준다. 현재 효과 없이 표시하는 수령·복용·시간 초과 대사에는 판정과 감정이 드러나는 어절을 지정해 한 번 이상 강조한다. 증상을 담은 짧은 문장은 강조 1회까지 허용한다. | 여섯 증상이 각각 다른 움직임으로 읽히고, 반응 대사에도 효과가 보인다. 고정·API 대사 모두 효과를 재생하며, 클릭 스킵은 즉시 본문을 펼치고 마지막 강조를 한 번 보여 준다. |
| **6. 텍스트 그림자** | 오더·작업실의 타이머, 본문·이름표, 버튼·프롬프트, 결과 카드와 입장 문구에 짙은 드롭 섀도를 적용한다. TMP는 UI 용도별 SDF Underlay 머티리얼 프리셋, 기존 uGUI Text는 Shadow 설정을 사용한다. 대사 잔상 레이어는 별도로 강도를 맞춘다. | 가장 밝은 조명과 버튼 배경에서도 글자가 읽히고, 작은 키캡과 결과 숫자의 획이 그림자에 묻히지 않는다. [Unity TMP Distance Field 셰이더 문서](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/ShadersDistanceField.html) |
| **9. 자간·행간** | 대사 본문의 현재 폰트와 크기에서 측정한 기본 글자 간격을 기준으로 **자간 −8%**, 줄 기준선 간 거리를 **+10%**로 맞춘다. TMP Inspector 값은 폰트 단위이므로 실제 글자·줄 간격을 기준으로 환산한다. HUD와 결과의 반복 라벨에도 자간을 맞추고, 행간 조정은 여러 줄 본문과 프롬프트 행에 적용한다. | 기존보다 글자가 조밀하고 줄 사이가 넓다. 기준 해상도 1280×720과 좁은 뷰포트에서 잘림 및 행 겹침이 없다. [Unity TextMeshPro 문서](https://docs.unity3d.com/Packages/com.unity.ugui@2.0/manual/TextMeshPro/index.html) |

**대사 구현 순서**는 자간·그림자 프리셋 → 완성된 본문 줄바꿈 → 글자별 효과 → 스크롤이다. 레이아웃 작업은 `OrderDialogueView`에서, 어절 공개 시점과 효과는 `DialogueTimeline`에서 관리한다. 개행 또는 TMP 태그 추가로 문자열 위치가 바뀌므로 본문·잔상·빗방울이 같은 글자 인덱스 매핑을 사용하도록 한다. 글자를 공개할 때는 이미 배치된 메시를 사용하고, 뷰포트 폭이나 폰트가 바뀔 때만 배치를 다시 계산한다. 주요 효과의 가장자리에는 마스크 여유를 확보한다.

## 2. 오더 씬 입장·반응·결과

| 요청 | 구현 | 완료 기준 |
| --- | --- | --- |
| **10. ‘손님입장’ 문구** | `Waiting` 또는 `Preparing`에서 처음 `Consult`로 진입할 때 1회 재생한다. 화면 아래에서 회전하며 던져져 포물선의 정점이 화면 정중앙을 지나게 한다. 정점 부근에서 이동과 회전을 느리게 하고, 하강하면서 화면 아래로 빠르게 빠지게 한다. 전체 0.8~1.0초부터 조정한다. | 상승은 빠르게 시작해 감속하고, 중앙을 통과하며 문구가 읽히고, 하강은 다시 빨라진다. 작업실에서 돌아올 때 재생되지 않는다. |
| **11. 손님 입장** | `OrderSceneView`의 최초 입장 재생에 초상화 모션을 붙인다. 별도 상위 `RectTransform`을 화면 오른쪽 밖에서 카운터 자리까지 약 0.35초 `Ease.InCubic`으로 이동한다. 정지 순간 리그의 몸통·머리·머리카락 계열 본에 시차를 둔 감쇠 진동을 약 0.3초 넣는다. 리그가 없는 초상화는 상위 컨테이너의 기울기와 레이어 변형으로 관성을 표현한다. | 빠르게 미끄러져 들어온 직후 몸과 머리가 과장되게 흔들린 뒤 자세가 안정된다. 눈·머리카락 등 초상화 레이어가 함께 따라온다. |
| **12. 대화 동작** | 대사 재생 시작과 선택된 강조 어절을 `PortraitRigModule`에 전달한다. 손님이 큰 고개 젖힘, 앞으로 숙임, 좌우 반동 중 대사에 맞는 동작을 하고 짧게 정착하게 한다. Spine은 기존 idle 위에 본 오프셋을 합성한 후 메시와 눈 위치를 갱신한다. 리그가 없는 손님에게는 동일한 타이밍에 컨테이너 동작을 적용한다. | 대사 중에는 첫 동작과 증상·감정 강조가 분명하고, 말이 끝나면 기본 동작으로 돌아온다. 새 손님과 결과 초상에 직전 포즈가 남지 않는다. |
| **7. 슬라임 변신** | `PortraitView.TransformIntoSlime`의 녹색 틴트를 살려 `충격과 수축 → 젤 파편과 순간 팽창 → 슬라임 스프라이트 교체 → 탄성 복원` 순서로 약 0.6초 재생한다. 오더 초상화 위에 재사용 가능한 VFX를 배치한다. 현재 카탈로그에 연결된 `POR_SLIME_BASE`를 사용한다. 교체와 탄성 동작 뒤 복용 반응을 이어 간다. | 외형이 바뀌는 순간을 눈으로 확인할 수 있고, 결과창에도 슬라임 초상이 표시된다. 두 번째 주문에서는 색과 크기가 초기 상태다. [Unity ParticleSystemRenderer 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/ParticleSystemRenderer.html) |
| **8. 결과창** | `RoundResultView.Show`를 취소 가능한 순차 표시로 확장한다. 첫 프레임부터 **재료·물약병·잉크·시간 보너스·총점** 라벨과 카드가 보인다. 값 칸을 비워 놓고 화면 위에서 아래로 각 행의 판정과 점수를 약 0.16초 간격으로 채운 뒤 총점을 표시한다. 마지막에 현재 판정에 해당하는 도장을 `알파 0 → 1`, `크기 약 180% → 100%`, 약 0.25초 `Ease.OutCubic`으로 찍는다. 크기 100%에 도달하는 프레임에 카드와 보이는 화면 레이어를 0.18~0.25초 흔들고 종료 후 다음 주문 버튼을 활성화한다. | 카드를 보면 처음부터 항목을 읽을 수 있고, 값이 위에서부터 채워진다. 도장과 흔들림이 100% 시점에 한 번만 맞물린다. 성공·실패·시간 초과 도장이 각 판정에 맞게 표시된다. |
| **13. 딤드 페이드** | 오더 커튼과 씬 이동이 공유하는 전체 화면 딤 레이어를 둔다. 커튼은 약 0.12초 어둡게 → 가장 어두운 프레임에 커튼 변경 → 약 0.18초 복귀로 연결한다. 씬 이동은 빠르게 어두워진 뒤 `LoadSceneAsync`가 끝나고 대상 화면이 나올 때 밝힌다. `SceneFlow`와 `RoundDirector.LoadSceneIfNeeded`의 호출을 공통 전환으로 연결해 타이틀 → 오더, 창고 왕복, 시간 초과 복귀를 처리한다. | 커튼과 장소가 바뀔 때 딤이 먼저 깔리고 새 화면에서 즉시 걷힌다. 연속 입력이나 이동 중 시간 초과에도 최종 씬이 맞고 화면이 어둡게 고정되지 않는다. [Unity LoadSceneAsync 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/SceneManagement.SceneManager.LoadSceneAsync.html) |
| **14. 불빛 플리커** | `01_Order`의 벽 랜턴 두 개에 이미 연결된 `Light2DFlicker`를 확장한다. 기준 강도에서 약 `±10%`의 연속적인 불규칙 변화와 간헐적인 더 큰 하락을 섞고 랜턴마다 다른 시드를 준다. 전역광의 기존 `Light2DIntensitySway` 진폭은 낮춰 벽 랜턴 주변의 변화가 읽히도록 한다. | 랜턴 둘이 다른 박자로 계속 미세하게 움직이고, 불빛이 닿는 주변에 변화가 보인다. 대사와 결과 UI의 대비는 안정적이다. [Unity URP 2D 조명 문서](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.0/manual/2DLightProperties.html) |

입장 순서는 **대사 준비 완료 → 커튼 전환 → 안내 문구와 손님 슬라이드 → 손님이 도착할 즈음 첫 어절 공개**로 맞춘다. 고정 대사와 API 경로가 같은 입장 연출을 타도록 배치하고, 기존 입장 대기 시간을 연출에 흡수한다. 타이머는 `RoundDirector`의 `Consult` 진입 시점에서 시작하며 입장 비용도 제한 시간에 포함된다. 씬 전환은 요청 즉시 진행 상태를 잠그고, 어두워진 뒤 씬을 전환한다. 전환 도중 타임아웃이 나면 `Ending`의 카운터 복귀를 우선한다.

## 3. 작업실 조작·재료 투입

| 요청 | 구현 | 완료 기준 |
| --- | --- | --- |
| **5. 플로팅 조작 프롬프트** | `WorkshopHud`의 단일 액션 문구를 `WorkshopCanvas/InteractionPrompt`의 세로 행으로 바꾼다. 각 행은 왼쪽 키캡과 오른쪽 동작 텍스트로 구성한다. 재료를 든 상태는 **[F] 주머니에 넣기**, **[R] 마우스로 돌리기**, **[우클릭] 돌려놓기**를 한 줄씩 표시한다. 집기·가마솥·조제 대기 상태에서는 사용할 수 있는 조작이나 상태 문구만 표시한다. | 재료를 든 동안 키가 각 행의 맨 앞에 표시되고, 세 동작을 각각 한 줄에서 읽을 수 있다. 화면 중앙 조준점과 겹치지 않는다. |
| **15. 주머니에 넣기** | `F`로 담기 시작하면 `WarehouseIngredient`의 화면상 3D 모델을 카메라 기준 아래로 약 0.25초 이동시키며 작게 만든다. 모델이 화면 아래로 빠지는 순간 슬롯 미리보기와 기존 주머니 소리를 갱신하고, 손의 모델을 숨긴다. 연출이 시작되면 이 재료의 회전·반환·중복 입력을 잠근다. | 손에 든 물건이 주머니로 들어가듯 아래로 사라지고 해당 슬롯에 같은 재료가 표시된다. 연속 입력으로 중복 보관되지 않는다. |
| **16. 가마솥 투입** | 소유한 재료 ID와 재생용 모델 참조를 슬롯 순서대로 보관한다. 가마솥에서 투입을 한 번 수락하면 카메라 아래의 꺼내기 지점에서 가마솥 입구까지 동일한 세 재료를 순서대로 날린다. 각 궤적의 XZ는 시작점과 도착점을 보간하고 Y에 포물선 높이를 더한다. 첫 조정은 재료당 약 0.35초, 발사 간격 약 0.20초다. 해당 모델이 입구에 도달할 때 슬롯을 비우고 투입음을 재생한다. | 세 재료의 종류와 순서를 알아볼 수 있고 각 물체가 곡선을 그려 가마솥 안으로 들어간다. 세 번째 착수 후 현재 4초 조제 카운트다운과 증기·반복 찰랑임이 시작된다. |
| **17. 수위 상승** | 재료가 물에 닿는 세 시점에 각각 `초기 → 1단계 → 2단계 → 3단계` 수위 목표를 순서대로 적용한다. `Cauldron.prefab`의 액체 렌더러에서 기존 `Liquid_Bubble` 수면 파라미터 `_Amount`를 `MaterialPropertyBlock`으로 약 0.15초 보간하고, 착수 시 짧은 찰랑임을 추가한다. 다음 재료가 닿기 전에 앞 단계 수위에 도달하게 하고, 실제 카메라에서 차이가 읽히도록 초기·최종 수위를 먼저 잡는다. | 착수마다 수위가 뚜렷하게 오른다. 마지막 수위가 가마솥 테두리 아래에 있고 기포와 수면이 함께 움직인다. 다음 배치에서 초기 수위가 복원된다. [Unity MaterialPropertyBlock 문서](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/MaterialPropertyBlock.html) |

`WorkshopInteraction`은 재료 보관·제출과 입력 상태를 관리하고, 연출 모듈은 모델 이동과 취소 시 정리를 담당한다. `WorkshopCauldron`은 투입 단계와 조제 시점을 관리하고 `LiquidMotion`은 수위와 찰랑임을 적용한다. 기존 `PocketModelDisplay`는 슬롯 미리보기에 재사용한다. 투입 개시에서 제출 조건을 한 번 검증하고 세 재료를 예약한다. 투입 중 중복 제출과 상호작용을 막고, 제한 시간 만료로 씬을 떠날 때 대기 중인 이동·음향·모델을 정리한다. 투입 시간은 기존 라운드 제한 시간에 포함하고, 4초 조제는 세 번째 재료 착수 뒤부터 센다.

## 구현 순서와 확인 범위

1. **대사와 타이포그래피** · 2·4·6·9. `DialogueTimeline`, `DialogueGlyphLayer`, `OrderDialogueView`와 `OrderCanvas`부터 적용한다. 고정·API 대사, 여섯 증상 효과, 긴 문장, 마지막 한 글자, 줄 끝 구두점, 스킵, 해상도 변경을 확인한다.
2. **오더 씬과 전환** · 1·3·7·8·10·11·12·13·14. 짧은 딤과 입장 타이밍을 먼저 연결하고, 손님 동작과 HUD를 맞춘 뒤 변신·결과 연출을 붙인다. 리그가 있는 손님과 없는 손님, 정상 결과와 시간 초과, 다음 손님까지 확인한다.
3. **작업실** · 5·15·16·17. 프롬프트 → 주머니 이동 → 투입 궤적 → 수위·기존 조제 효과 순으로 연결한다. 취소, 짧은 연속 입력, 세 재료 착수, 조제 시작, 카운터 복귀까지 확인한다.

간단한 트윈에는 LitMotion, 순차 재생에는 UniTask와 단계별 취소 토큰을 사용한다. 표의 속도·각도·강도는 Inspector 튜닝 시작값이다. 구현 시 기존 Unity Editor를 확인해 사용하고, 먼저 컴파일과 씬·프리팹 참조를 확인한 뒤 화면 동작을 실제 흐름에서 점검한다.
